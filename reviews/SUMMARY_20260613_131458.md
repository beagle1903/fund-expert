## 🔴 P0 Findings (Critical / Immediate Fix Required)

### 1. Performance: CLI Startup Delay Due to Eager Imports
**Issue:** The CLI takes 1.5–2.5 seconds to start because heavy libraries (`pandera`, `pandas`) are imported globally before asking for user input, creating a severe UX bottleneck.
**Suggested Fix (Actionable Prompt):**
> "Refactor `fundexpert/cli.py` to defer heavy module imports (`pandas`, `pandera`, `pipeline`) until *after* `prompt_user` finishes gathering interactive input. Ensure the CLI launches instantly."

## 🟠 P1 Findings (High Priority)

### 1. Business Logic: Missing Risk Value Causes History Save Crash
**Issue:** `fundexpert/history/store.py` assumes `risk` is always a valid float. If a fund lacks an SRRI risk value (`NaN`), `int(r["risk"])` throws a `ValueError` and crashes the entire pipeline during the save process.
**Suggested Fix (Actionable Prompt):**
> "Fix `save_run` in `fundexpert/history/store.py` to safely check `pd.notna(r['risk'])` before casting to `int`, falling back to `None` if missing."

### 2. Architecture: Implicit Coupling to Global State
**Issue:** Domain functions (scoring, picking, weighting) import global configuration directly from `fundexpert.config`, making testing and multi-tenant scaling difficult.
**Suggested Fix (Actionable Prompt):**
> "Refactor the domain functions in `fundexpert/` to use Dependency Injection for configuration values instead of importing global state. Introduce a `ScoringConfig` or similar dataclass."

### 3. Architecture: Concurrency Tightly Coupled to Domain Logic
**Issue:** `news/penalty.py` hardcodes a `ThreadPoolExecutor` internally to fetch news, mixing execution models with domain logic.
**Suggested Fix (Actionable Prompt):**
> "Extract the `ThreadPoolExecutor` from `news/penalty.py`. The `apply_negative_news_penalty` function should accept an `Executor` interface or abstract the concurrent fetching entirely."

### 4. Test Coverage: Unexercised Negative Paths & Exception Handlers
**Issue:** Several `except OSError` and `except ValueError` blocks in `tavily.py`, `store.py`, `cli.py`, and `ui.py` lack test coverage.
**Suggested Fix (Actionable Prompt):**
> "Write unit tests targeting the exception handlers in `tavily.py`, `store.py`, `cli.py`, and `ui.py`. Use `unittest.mock.patch` to simulate file I/O (`OSError`) and JSON parsing errors to ensure graceful fallbacks."

### 5. Performance / Architecture: Pandera Validation Overhead
**Issue:** `pandera` validation adds ~150-200ms of runtime overhead on every data load in `merge_universe`.
**Suggested Fix (Actionable Prompt):**
> "Modify `fundexpert/data/merge.py` to conditionally skip Pandera validation in production runs based on a flag or environment variable, reserving strict validation for test suites."

## 🟡 P2 Findings (Medium Priority / Tech Debt)

### 1. Test Coverage: Missing Property-Based Tests for Scoring
**Issue:** While selection/weights use Hypothesis, `scoring/score.py` only has parametrized tests and lacks rigorous invariant checking.
**Suggested Fix (Actionable Prompt):**
> "Implement Hypothesis property tests for `scoring/score.py` ensuring invariants: 1) Score values stay within bounds, 2) Monotonicity with respect to returns, 3) Strict risk penalty application."

### 2. Business Logic: Weighting Invariant Violation (N > 20)
**Issue:** Passing `N > 20` programmatically causes `compute_weights` to assign 0% to some funds, violating the >=5% minimum weight rule.
**Suggested Fix (Actionable Prompt):**
> "Enforce `N <= 20` inside `pick_top` or `run_pipeline`, raising an explicit `ValueError` if exceeded to prevent invariant violations."

### 3. Business Logic: Strict Horizon Exclusions
**Issue:** `apply_horizon` uses `skipna=False`, strictly dropping any fund missing even a single month in a long horizon bucket (e.g. a 4.5 yr fund dropped from 5 yr calculation).
**Suggested Fix (Actionable Prompt):**
> "Review `apply_horizon` logic in `fundexpert/scoring/horizon.py`. Consider using `skipna=True` or a weighted imputation strategy to retain slightly incomplete historical data."

### 4. Architecture / Business Logic: Rules Engine Hardcoding & Overlaps
**Issue:** Strategy and sector mappings are hardcoded Python dicts. Additionally, "ALTIN" and "KIYMETLİ MADEN" overlap in both strategy and sector rules, unnecessarily double-penalizing gold funds under diversity caps.
**Suggested Fix (Actionable Prompt):**
> "Extract `_BUCKET_RULES` and `_SECTOR_RULES` into a `rules.yaml` file. Remove the gold keywords from `_SECTOR_RULES` so they only apply to the strategy cap and default to 'diversified' sector."

### 5. Performance: Python-level Loop for String Normalization
**Issue:** `turkish_upper` uses a list comprehension in pandas, missing vectorization benefits.
**Suggested Fix (Actionable Prompt):**
> "Refactor string normalization in `fundexpert/pipeline.py` to use vectorized pandas `.str` operations or a highly optimized `apply` mapping."

### 6. Architecture: Fragile Data Contracts Between Stages
**Issue:** The pipeline stages mutate DataFrames implicitly without intermediate schema validation, coupling downstream consumers to upstream mutations.
**Suggested Fix (Actionable Prompt):**
> "Implement internal `pandera` schemas for intermediate pipeline stages (e.g., `ScoredCandidatesSchema`) to strictly define column contracts before picking and weighting."

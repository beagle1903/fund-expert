# Parallel Code Review Summary — 2026-06-12

## Executive Summary
A comprehensive parallel code review was conducted across 5 domains: Security, Architecture, Test Coverage, Performance, and Business Logic. The `fundexpert` codebase is generally robust and well-structured, but the review identified 2 critical (P0) issues related to pipeline crashes and network cache corruption, 7 significant (P1) issues ranging from injection vulnerabilities to inefficient string manipulation, and 9 minor (P2) improvements.

Below is the prioritized synthesis of all findings and their corresponding actionable AI agent prompts.

## 🚨 P0 Findings (Critical)

### 1. Missing `risk` values cause pipeline crash (Business Logic)
- **Issue**: TEFAS exports can have missing `Fonun Risk Değeri` (e.g., "Serbest" funds). These propagate as `NaN` into the scoring pipeline, evaluating risk penalty to `NaN`. This ultimately causes fatal crashes in `select/weights.py` when attempting to cast to `int` and in `render/table.py`.
- **Agent Prompt**: `In fundexpert/scoring/score.py, impute missing risk with 7.0 using out["risk"].astype(float).fillna(7.0) before computing the risk penalty. In fundexpert/render/table.py, use str(int(r["risk"])) if pd.notna(r["risk"]) else "-" for safe rendering.`

### 2. Network Cache Stampede & Data Corruption Risk (Performance)
- **Issue**: `ThreadPoolExecutor` concurrent queries for funds sharing the same portfolio company result in identical Tavily queries being executed in parallel. These threads read the empty cache simultaneously, make redundant API calls, and then write to the exact same JSON file concurrently, leading to data corruption and rate limit exhaustion.
- **Agent Prompt**: `Refactor apply_negative_news_penalty to extract a set of unique company_prefix values from the top-K candidates. Map these unique prefixes to the ThreadPoolExecutor instead of querying per-fund. After queries complete, broadcast the results back to the respective funds. Additionally, modify _write_cache in news/tavily.py to write JSON to a .tmp file and rename it atomically.`

## ⚠️ P1 Findings (Significant)

### 3. Terminal Output Manipulation / Rich Markup Injection (Security)
- **Issue**: Untrusted CSV data and external API strings are passed to the `rich` console. An attacker controlling the CSV or a compromised news website can inject `[tags]` to manipulate terminal display or drop malicious links.
- **Agent Prompt**: `Fix Rich markup injection in fundexpert/render/table.py. Import rich.markup.escape and wrap all untrusted variables (e.g., item['title'], item['url'], item['source'], r['fon_adi']) with escape() before passing them to console.print or table.add_row.`

### 4. Duplicated and Incomplete Turkish Text Normalization (Architecture & Performance)
- **Issue**: Turkish string casing (`str.replace("i", "İ").replace("ı", "I").upper()`) is repeated manually across `pipeline.py`, `strategy.py`, `sector.py`, `match.py`, and `tavily.py`. In `pipeline.py`, it's done repeatedly per row, creating a CPU and memory allocation bottleneck.
- **Agent Prompt**: `Create a new module fundexpert/utils/text.py containing turkish_upper and turkish_lower helper functions. In pipeline.py, pre-compute a Turkish-uppercased Series of fon_adi using vectorized string operations. Refactor strategy.py, sector.py, match.py, and tavily.py to use the centralized helpers and pre-uppercased strings.`

### 5. Incomplete sector definition allows gold concentration (Business Logic)
- **Issue**: `ALTIN` and `KIYMETLİ MADEN` are mapped to strategy but not to sector buckets. They fall back to `"diversified"`, avoiding the sector cap entirely, which can lead to a portfolio over-concentrated in gold funds.
- **Agent Prompt**: `In fundexpert/select/sector.py, add ("ALTIN", "precious_metals") and ("KIYMETLİ MADEN", "precious_metals") to the _SECTOR_RULES tuple (place them before the "METAL" rule).`

### 6. Untested Client-Side Keyword Validation for Tavily Hits (Test Coverage)
- **Issue**: The Turkish case-normalization and keyword filtering logic dropping false-positives in `tavily.py` is entirely untested.
- **Agent Prompt**: `Add unit tests to test_news_tavily.py for the client-side keyword filtering logic in _post_tavily. Ensure you test that false-positive results are dropped, and that Turkish characters (I/ı, İ/i) are matched case-insensitively.`

### 7. Missing Property-Based Tests for Complex Algorithms (Test Coverage)
- **Issue**: Algorithmic invariants in weight allocation (sum = 100%, multiples of 5%) and diversity caps (max per sector/strategy) lack property-based testing to verify correctness against randomized data.
- **Agent Prompt**: `Install hypothesis and add property-based tests to test_weights.py and test_pick.py. For weights, assert the sum is 100 and multiples of 5. For pick, assert max_per_type and max_per_sector are strictly respected across arbitrary candidate DataFrames.`

### 8. DataFrame Iteration Bottleneck in Selection (Performance)
- **Issue**: Using `sorted_df.iterrows()` inside `pick_top` heavily incurs type-boxing overheads and slows down the candidate selection.
- **Agent Prompt**: `Replace sorted_df.iterrows() in fundexpert/select/pick.py with sorted_df.itertuples(index=True, name='Row') and adjust column accesses to avoid the pandas Series allocation overhead of iterrows.`

### 9. Tightly Coupled Exception Handling in API Client (Architecture)
- **Issue**: `query_negative_news` catches exceptions and prints directly to `sys.stderr`, preventing callers from capturing or suppressing output cleanly.
- **Agent Prompt**: `In fundexpert/news/tavily.py, replace the print(..., file=sys.stderr) call in query_negative_news with logger.warning(...) to decouple console output from the API fetching logic.`

## 🛠️ P2 Findings (Improvements & Tech Debt)

### 10. Arbitrary File Overwrite via Symlink Attack on Cache Files (Security)
- **Issue**: Cache and history files (`last.json`, `news_cache/*.json`) written insecurely, risking symlink local file overwrites.
- **Agent Prompt**: `Fix symlink vulnerabilities in cli.py, history/store.py, and news/tavily.py. Update file writing to use tempfile.NamedTemporaryFile(delete=False, dir=path.parent) followed by an atomic os.replace().`

### 11. Unbounded Memory Consumption during CSV Loading (Security / Performance)
- **Issue**: Using `pd.read_csv` without limits can exhaust memory. Also, the default C engine is less efficient than PyArrow.
- **Agent Prompt**: `Harden fundexpert/data/loader.py against overly large CSVs. Check path.stat().st_size before calling pd.read_csv (raise ValueError if >50MB). Additionally, specify engine='pyarrow' for better performance.`

### 12. Fragile Turkish keyword matching due to Python `lower()` (Business Logic)
- **Issue**: `k.lower()` on uppercase `"İ"` generates `"i\u0307"`, breaking keyword matching in Tavily results.
- **Agent Prompt**: `In fundexpert/news/tavily.py, update the client-side validation to normalize the keyword k: k_clean = k.replace("I", "ı").replace("İ", "i").lower() before checking against the text.`

### 13. Missing Deterministic Tie-Breaking in Selection (Architecture)
- **Issue**: `scored.sort_values` on `score` lacks a secondary key, causing unstable sorting on ties.
- **Agent Prompt**: `Modify fundexpert/select/pick.py to sort candidates by ['score', 'fon_kodu'] with ascending=[False, True] for deterministic tie-breaking.`

### 14. Hardcoded Constants and Magic Dictionary Keys (Architecture)
- **Issue**: `_STEP = 5` is hardcoded. `loader.py` returns magic dict keys instead of a typed structure.
- **Agent Prompt**: `Move _STEP = 5 from weights.py to config.py as WEIGHT_STEP_PCT. Refactor loader.py to return a strongly-typed UniverseData dataclass instead of a dictionary.`

### 15. Candidate Filtering Rules Mixed Into Orchestration (Architecture)
- **Issue**: `run_pipeline` in `pipeline.py` implements DataFrame `.dropna` filtering logic natively.
- **Agent Prompt**: `Extract the NaN-dropping logic for applied_management_fee_pct and ret_3m from fundexpert/pipeline.py into a new clean_candidates(df) function inside fundexpert/data/merge.py.`

### 16. Dead Code in Data Loader and Scoring (Performance / Business Logic)
- **Issue**: `max_total_expense_pct` is parsed but never used. `_breakdown` list comprehension constructs ~1000 unused dicts during scoring.
- **Agent Prompt**: `Remove the max_total_expense_pct mapping from YONETIM_RENAME in loader.py. Remove the _breakdown column assignment and comprehension from scoring/score.py.`

### 17. ThreadPoolExecutor Unhandled Exceptions (Test Coverage)
- **Issue**: A crash in one Tavily query thread will propagate out of `future.result()` and kill the entire script.
- **Agent Prompt**: `In penalty.py, wrap the future.result() call inside the ThreadPoolExecutor loop in a broad try-except block to gracefully skip failures.`

### 18. Minor Untested Edge Cases (Test Coverage)
- **Issue**: `_ensure_utf8_stdio` OS interactions and empty DataFrame scoring behaviors lack unit tests.
- **Agent Prompt**: `Add unit tests covering _ensure_utf8_stdio in test_cli.py (mock sys.stdout) and verify empty DataFrame handling in test_score.py and test_normalize.py.`
